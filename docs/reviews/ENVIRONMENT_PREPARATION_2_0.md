## Implementation brief

The isolated fresh-browser prototype uses supported PMREMGenerator/fromCubemap and renderer compile/render-target APIs; a private proxy compiles prospective filter draws rather than executing them. A 1×1 scratch framebuffer avoids allocating full-resolution seed targets. ## Quality-change failure found and fixed

The first new compact quality-wait fixture failed: the canvas disappeared while held filter shaders were pending. A diagnostic captured the actual readable failure state, no uncaught page error and 113 completion polls; this was not accepted as a pass. The shared poller had retained native handles for old scene programs that a quality update legitimately disposed. It now filters those retired handles before each status query, while still rejecting a lost context, deadline, thrown query or unsuccessful linkage. Owned seeds stay alive until the replacement environment acquires its programs.

A preparation marker covers the cleared DPR buffer with the existing reserved poster, then exposes the canvas only after its first replacement draw. It does not change parent readiness or reset ObjectModel/playback. Source startup checks increase from 52 to 72: both widths deliberately hold a native quality change, check canvas identity and fallback/live visibility, confirm program retirement and zero disposed-handle status queries, and check no browser errors/API mutation. Existing cancellation/failure/linkage/missing-capability checks still pass. The independent quality suite now waits for an actual completed draw before measuring, instead of relying only on a fixed warm-up delay.
