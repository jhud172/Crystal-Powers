## Staff account security added 16 October 2026

Team Settings now includes self-service password change, sign out everywhere and authenticator replacement. Each requires the current password and a fresh, unused current authenticator code. Replacement keeps the old key active until a valid new-key code is confirmed; cancellation leaves it active. A lost password/authenticator still requires an admin-issued private recovery invitation after identity checking. The protected owner uses the separate owner security controls.

Authenticated, CSRF-protected POST contracts under `/api/team/account`: `/password` takes `{password,code,nextPassword}`; `/sessions/revoke` and `/authenticator` take `{password,code}`; `/authenticator/confirm` takes `{code}`; `/authenticator/cancel` has no body. No request accepts a target member/workspace. Proof attempts share an account-keyed limit of 10 attempts per 15 minutes. Begin returns only the private setup key; the server session stores its encrypted form with actor/version and a five-minute deadline. Successful password/revocation/replacement increments the credential version and ends the current session; password/replacement also invalidate outstanding invitations. Other accounts and owner credentials are unaffected.

Credential mutations use current workspace/account locks and conditional version checks. The UI clears private fields after confirmed changes, preserves rejected correction input, locks overlapping actions, protects unsaved work and requires fresh sign-in after an uncertain mutation. Secrets are not put in browser storage/draft recovery. No schema or dependency changes were required. Exact H2/PostgreSQL and packaged synthetic browser evidence is recorded in the latest staff-security progress checkpoint; whole recovery/concurrency/device/deployment acceptance remains open.
