## Responsive layouts and adaptive effects

Screen dimensions determine composition; they do not prove GPU speed. `renderQuality.ts` sets a conservative starting tier; `useAdaptiveRenderQuality.ts` now observes sustained active frame cadence in the device and logo views. This is responsiveness evidence, not GPU identification or thermal certification. Physical-device acceptance remains open.

| Profile | Composition and interaction | Effect budget |
| --- | --- | --- |
| Compact / constrained | 320–480px, narrow landscape, short heights, coarse pointer; readable stacked content and thumb-friendly controls | Fewer simultaneous effects, capped DPR, lower mesh/texture/environment cost, simplified glass/shadows/particles and inexpensive transitions |
| Balanced | Tablet/intermediate windows and typical laptops; portrait/landscape layouts and mixed input | Rich interactions with bounded materials/lighting; measured downshift when frame times degrade |
| Full immersive | Spacious capable desktop/wide screens with enough measured headroom | Highest polished geometry/lighting and richer layered animation; preserve text hierarchy and control clarity |
| Reduced / still | System reduced motion, explicit reduced effects, unavailable WebGL, or sustained poor performance | Intentional stills and immediate/low-motion state changes with all content/actions retained |

- [ ] **ADAPT-01** Implement and visually review 320, 390, 480, 768, 1024, 1440, 1920 and 2560px representative widths, plus short/tall windows, portrait/landscape, intermediate resizing and 200% zoom/reflow. Avoid clipping or vast empty expanses.
- [ ] **ADAPT-02** Combine conservative initial defaults, supported capability hints and measured rendering cost. Use stable downshift/recovery thresholds with hysteresis/cooldowns; avoid constant quality changes. Missing hints are unknown, not proof of a powerful device.
- [ ] **ADAPT-03** Expose clear automatic/lighter/richer quality, animation pause and reduced-effects choices through the existing experience controls. Explicit reduced motion takes precedence; quality changes retain state and do not remount unrelated forms.
- [ ] **ADAPT-04** Record asset transfer, deferred chunks, first useful content, input responsiveness, layout shifts, frame-time distribution and sustained operation for representative tiers. Aim for smooth 60fps animation on capable devices and a stable lighter experience on constrained devices; record actual results rather than inferring them from viewport size.
- [ ] **ADAPT-05** Verify real physical devices separately for scrolling, touch, GPU limits and sustained/thermal behaviour. Browser viewport emulation is only responsive-layout evidence.
