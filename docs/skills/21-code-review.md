# 21 - Code Review

## Purpose

Use when asked to review code, PRs, diffs, or risky changes.

## Review Order

1. Correctness.
2. Security.
3. Data integrity.
4. Accessibility.
5. Performance.
6. Maintainability.
7. Consistency.
8. Visual quality.

## Findings Must Include

- Severity.
- File.
- Line or component.
- Impact.
- Recommended correction.

## Rules

- Lead with findings.
- Do not focus on formatting while missing functional faults.
- Separate blocking issues from minor cleanup.
- Mention test gaps and residual risk.
